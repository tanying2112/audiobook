马具迭代完整方案

Audiobook Studio 自我进化体系 —— 不训练模型，只迭代 Prompt / SOP / 阈值 / 路由。接入离线 Ollama + Qwen3.5-2B 后，迭代成本降为零，可常态化运行。

二、离线 LLM 接入（Ollama + Qwen3.5-2B）

本地 Ollama 使自迭代摆脱免费 API 配额约束——反思、prompt 改写、金丝雀判分全部可离线跑。Qwen3.5-2B 承担"教练"角色；生产主路由仍走免费云 API（质量更高），自迭代回环用本地模型。

配置

# .env
OLLAMA_BASE_URL=http://localhost:11434
SELF_ITERATION_LLM=ollama/qwen3.5:2b      # 自迭代专用模型
SELF_ITERATION_MOCK=false                  # 真实运行（走 Ollama）
SELF_ITERATION_BATCH_SIZE=20               # 攒 20 条纠错样本触发一轮反思
GOLDEN_CANARY_SUBSET=8                     # 金丝雀每 stage 抽 8 条

litellm 原生支持 ollama/qwen3.5:2b 协议，create_router 增加 provider 条目即可，无需改管线代码。

模型分工

角色模型理由
生产管线（extract/annotate/edit）免费云 API 轮换池质量优先，配额内
自迭代教练（归因、prompt 改写）本地 Qwen3.5-2B无限量、离线、可批量
晋升判分（golden pass/fail）规则 + 硬指标为主，LLM-Judge 用云端判分可信度必须高于被测对象

三、实施步骤（4 个里程碑）

M1 · 闭环打通（第 1 周）

  1. Ollama provider 接入 create_router，写 3 个集成测试（路由命中 / 超时降级 / mock 切换）。
  2. CorrectionCollector 落库确认：每次质量门禁失败 + 人工编辑差异，生成统一 schema 的纠错记录（stage、input、output、缺陷类型、修复后样本）。
  3. ReflectionEngine 批量化：SELF_ITERATION_BATCH_SIZE 攒批触发，输出结构化归因 JSON（缺陷类别 × stage × 频次）。
  4. 失败案例自动回流 golden 集 data/golden/val/（不进 train，防污染）。

验收：跑通一次完整闭环 —— 注入 20 条人工构造的失败样本 → 生成归因报告 → 至少 1 条 SOP 规则 + 1 个候选 prompt 落盘 → golden val 集条目数增长 ≥ 10。

M2 · Prompt 自动进化（第 2–3 周）

  1. DSPy BootstrapFewShot 对 6 个文本 stage 各生成 3 个候选 prompt（把高纠错率案例编译为 few-shot 示例）。
  2. 金丝雀 A/B：_run_stage_with_prompt_version() 在 golden train 子集（每 stage 8 条）上对比 v1 vs 候选。
  3. 晋升门禁执行（见第四节 4 项标准），通过者写入 prompts/{stage}/v{N}.j2 并 shadow 10% 流量。
  4. GEPA 式反思变异（可选增强）：本地 Qwen 对失败样本做"为什么这个 prompt 错了"归因 → 生成变异 prompt → 进候选池。

验收：至少 2 个 stage 出现 prompt 晋升；晋升后 golden val 集 pass rate 不降；shadow 期硬指标（DNSMOS/WER）无统计显著退化。

M3 · 阈值与路由数据驱动校准（第 3–4 周）

  1. 收集 2 周生产硬指标分布（DNSMOS、WER、speaker_sim），对人工返工样本做分布对齐，重估 dnsmos_min / asr_wer_max / speaker_sim_min。
  2. 路由表进化：speaker_sim 失败的（角色, 声线）对自动降权 10%，连续 3 次失败移出映射候选。
  3. 阈值变更走同样的晋升门禁：在 golden 音频集上验证新阈值不放宽真实缺陷漏检。

验收：阈值调整有分布数据支撑（报告含前后分布图）；路由降权后跨章声纹一致性失败率下降 ≥ 20%。

M4 · 常态化运营（持续）

  1. 每日定时：攒批反思（Ollama，夜间跑）→ 周报（归因分布、晋升记录、阈值漂移）。
  2. 每周：全量 golden 回归（三集），产出进化曲线（各 stage pass rate 随版本变化）。
  3. 每月：SOP 库治理 —— 条目数上限 200，低命中规则归档；prompt 膨胀检查（token 数上限）。

验收：连续 4 周周报产出；golden 集规模月均增长 ≥ 30 条；无一次未过门禁的 prompt 进入生产。

四、晋升门禁与验收标准（核心护栏）

#标准量化口径不通过处理
1质量提升候选 prompt 在 golden train 子集 pass rate ≥ 现版 +2pp候选废弃，归因入 SOP
2无回归golden val 集 pass rate 下降 < 1pp；硬指标（DNSMOS/WER）无显著退化回滚 + 告警
3格式合规输出 schema 校验通过率 = 100%候选废弃
4样本充分金丝雀样本 ≥ 8 条/stage；晋升决策需 ≥ 2 个独立批次佐证延后，攒样再评

Shadow 全量门槛：shadow 10% 流量跑 7 天，硬指标均值不低于基线 95%，方可 100% 切换。

五、风险与对策

风险对策
本地 2B 模型归因质量不足，产出噪声规则规则仅入 SOP 候选区，晋升需门禁 + 人工抽检（每周 10 条）
golden 集被失败案例污染，评估失真train/val/test 三集隔离；回流只进 val；test 集冻结仅人工维护
Prompt 无限膨胀拖慢生产token 上限硬校验；few-shot 示例按效果末位淘汰
自我迭代"进化"出指标刷分（过拟合 golden）test 集从不参与进化循环；季度引入全新人工样本
免费云 API 配额耗尽影响生产判分LLM-Judge 可降级为纯硬指标门禁（DNSMOS+WER 已可用）

六、总验收清单

  • Ollama provider 接入，3 个集成测试通过
  • 一次完整闭环演示：失败样本 → 归因 → 候选 prompt → 金丝雀 → 门禁裁决
  • ≥ 2 个 stage 完成真实 prompt 晋升（非 mock）
  • golden 三集隔离机制生效，val 集持续增长
  • 阈值校准报告含分布数据，路由降权生效
  • 晋升门禁 4 标准全部强制执行，有回滚演练记录
  • 周报机制跑满 4 周

方案定位：马具迭代是免费约束下唯一可行的进化路径——每轮成本 = 本地 GPU 电费 + 数百次免费 LLM 调用，收益直接体现在 golden pass rate 与硬指标上，且门禁保证只进不退。
