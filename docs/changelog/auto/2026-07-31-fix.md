### Bug Fixes

#### Fix(pipeline)

- unblock end-to-end production pipeline — annotate/synthesize/quality persistence fixes ([HEAD](https://github.com/tanying2112/AI_Lab/commit/HEAD))

  Three distinct production bugs were preventing the audiobook pipeline from
  completing end-to-end (extract→analyze→annotate→edit→audio_postprocess→
  review→synthesize→quality). Each bug was reproduced via real fcc-gateway LLM
  calls on the test_story fixture (deepseek-v4-flash-free), root-caused, and
  covered by a regression test.
  Bug 1 (annotate creates phantom idx=0 paragraph):
    AnnotateStage.apersist/persist computed para_index via
    getattr(result, "paragraph_index", paragraph_index or 0), trusting
    the LLM-returned ParagraphAnnotation.paragraph_index FIRST and only
    falling back to the caller's value when the attribute itself was missing.
    In production, deepseek returned paragraph_index=0 for every paragraph,
    causing write_annotate to INSERT a bogus Paragraph(index=0, text="") with
    the real paragraph's annotation. The phantom paragraph then crashed:
      - synthesize: TtsRoutingInput text='' min_length=1 violation
      - quality: MultipleResultsFound on TTSEdit lookup
    Fix: caller-provided paragraph_index (ground truth from the CLI loop) wins;
    the LLM value is a last-resort fallback only.
    Regression test: test_annotate_apersist_uses_ground_truth_paragraph_index
  Bug 2 (synthesize/quality crash on multi-version rows):
    write_synthesize used
      select(AudioSegment).filter(...paragraph_id == para.id)
    and write_quality used
      select(TTSEdit).filter(...paragraph_id == para.id).order_by(version.desc())
    Both called scalar_one_or_none(), which raises MultipleResultsFound
    when the paragraph has >1 versioned row. Both models DO support multiple
    versions per paragraph (each has a version column), so the query
    intent was clearly "fetch the latest" — but the wrong SQLAlchemy method
    was used. Fix: add .order_by(version.desc()).limit(1) so the query
    returns at most one row, matching scalar_one_or_none()"'s contract.
  Bug 3 (synthesize/quality path did not mirror pre-review empty filter):
    cli/pipeline.py pre-review paragraph loop already filtered empties:
      valid_paras = [p for p in paragraphs if p.text and len(p.text.strip()) >= 10]
    but the post-review synthesize/quality loop ran ALL paragraphs unfiltered,
    so any empty / stub paragraph still in the DB (from older sessions or stub
    seed data) crashed synthesize with TtsRoutingInput text=''. Fix: apply
    the same valid_paras filter to the post-review loop for symmetry.
  Bug 0 (pause_before_ms NOT NULL violation during annotate UPDATE) — earlier
  in this session, regression test test_write_annotate_survives_null_pause_after_extract
    covers the pause_*_ms = result.pause_*_ms or 0 coalescing fix in
    persistence.write_annotate.
