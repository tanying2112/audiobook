Critical · 阻断目标成立的问题

这五条不修复，「免费资源下可自我迭代进化」的目标就无法达成。

C1

自我迭代闭环：管道真实、学习信号全为桩

核心主张的成色核查——SOP 反思、晋升门禁、DSPy/GEPA 的每一次质量信号都不是真实学习。B1 自迭代验证默认走确定性 mock LLM；音质指标是合规启发式（音色绑定覆盖率/情感默认覆盖率/角色解析率）而非真实听感；LLM-as-judge 是"文本模拟音频分析"；DSPy GEPA 分支内部用 MockLM，脚本自述「分数恒为 0、optimized_prompt 不变、perplexity drop=0 属已知限制」。金标集每阶段仅 3 例。系统今天无法真正自我改进，也无法自我证明它改进了。

High · 应尽快修复

H1

安全默认薄弱：限流默认关闭 + 注册默认开放

RATE_LIMIT_ENABLED=False、AUTH_REGISTRATION_MODE=open 均为默认。面向免费云 Studio 的定位下，开放注册叠加无限流 = 注册滥用/配额打爆面。注册/登录端点当前无频控。

settings.py:87,161
H2

LLM-judge 异常回退误标「敏感内容」

judge_quality 任何异常（网络抖动、超时）都返回 issues=["sensitive_content"] 并 needs_regeneration=True——一次瞬时错误会把内容误判为涉敏并触发强制重合成，还可能引发重合成死循环。错误路径应降级为「待人工」而非编造结论。

judge.py:95-114
H3

测试非 hermetic：并发共享可变运行时文件

首次全量跑 20 失败，同命令重跑（无并发干扰）0 失败。根因是并发 pytest 进程共享 audiobook_studio.db / test_indexes.db / storage/ 等运行时文件相互踩踏。CI 若并行/多次复跑会不稳定。

P0 · 让「可自我迭代进化」目标成立

  1. 接入真实音质评测信号，替换启发式合规指标 约 3–5 天

    根因：学习信号失真。合规覆盖率与「好听」无关，导致闭环优化优化的是错的目标。

    验收：新增质量层基于真实音频特征（UTMOS 或 SpeechLMScore）产出可复现分数；judge 调用真实模型而非文本模拟；golden 数据据真实分数量化「改进」。

  2. 自我迭代默认接真实 LLM，MockLM 仅作显式降级 约 2–3 天

    B1 默认确定性 mock、GEPA 用 MockLM——管道跑通了，但没有任何真实推理进入学习。

    验收：无 MOCK_LLM 时闭环消费真实生产样本并真实调用 LLM 反思；移除 GEPA「drop=0 豁免」；增益由外部 judge 独立验证而非自证。

  3. 拆除覆盖率 omit，真实覆盖率 ≥85% 约 3–5 天

    约 4900 行最核心代码被排除；即便如此仍 83.21% 未达门禁。

    验收：coverage run（仅排除 tests/migrations/__init__）≥85%；CI 门禁真实生效。

  4. 翻译功能取消模块级 skip 并补全测试 约 1–2 天

    有真实实现却整模块零测试，是「存根伪装真实」。

    验收：test_translate 全绿；翻译模块计入覆盖率。

  5. 语音试听复用真实合成引擎，修复死桩 约 0.5 天

    底层 /api/tts/stream 已能产出真音频，试听却指向 404。

    验收：GET /voices/preview/{id} 返回可播放 MP3；前端试听全流程可用。

P1 · 生产级加固

  1. Redis 不可用时代码降级，兑现「零配置启动」约 2–3 天

    README 承诺断网/零配置，但 Redis 是硬依赖。

    验收：无 Redis 下 uvicorn 成功启动，核心路径（含本地 TTS 合成）可用；可选用项优雅禁用。
